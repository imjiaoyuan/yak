# AGENTS.md

This file is the single contributor guide and authoritative architecture reference for working with code in this repository.

## Overview

`llm` is a single-binary, terminal-first coding agent in Rust, the reference-shaped: one executable, one agent (ten built-in tools, approvals, skills, memory, compaction, an interactive REPL), a thread-file session store, and an out-of-process extension host standing in for the reference's TS extensions. On top sit kept extensions the reference lacks: multimodal input (`-a/--attachment` path/URL/stdin + `--at PATH MIMETYPE`; in a session ctrl+v pastes the clipboard image as a temp-file path and any local image path in a message auto-attaches). Behavioral references: `the behavioral spec` (agent loop, tools, streaming REPL, extension shape), `the approval reference` (approval model), read-only and never built. The old `llm`-reference prompting half (prompt, templates, logs, schemas, embeddings, fragments) was removed wholesale — see Project state.

Command semantics, flags, storage, and output formats are specified in the docs.

## Commands

- `cargo build` / `cargo build --release` (release profile: thin LTO, strip, codegen-units=1)
- `cargo test` — unit tests live inline as `#[cfg(test)]` modules across the tree, one behavior per test under a descriptive name (`boundaries_clamp_to_char_edges`, never `test_foo`); run a single one with `cargo test <name>`. A test that needs a scratch directory takes one from `core/testutil` (`scratch_dir` creates it empty, `scratch_path` hands back an absent path for the tests that assert on what a missing tree does) — never hand-roll `env::temp_dir().join(...)`, and never key a name on `process::id()` (it does not separate the parallel threads of one test binary)
- `cargo fmt` before committing; keep `cargo clippy --all-targets` at zero warnings
- CI (`.github/workflows/ci.yml`) runs test → build → `ci_e2e.py` → `ci_repl.py` on ubuntu, macOS
  and windows-latest; the two Python scripts are CI-local harnesses, not shipped code. `ci_repl.py`
  skips itself on Windows, so run it on Unix to exercise the terminal paths.
- `README.md` embeds every command's full `-h` output verbatim — when flags or help text change, refresh the matching block there too (keep it byte-identical)
- Try the binary: `LLM_USER_PATH=/tmp/x cargo run -- "task"` — every path resolves under that dir, so smoke tests are hermetic
- Env overrides: `LLM_USER_PATH` (above), `LLM_MODEL` (beats the stored default and loses only to `-m`), `LLM_SHELL` (the shell behind every spawned command: agent bash, `!cmd`; the platform default is `sh`/PowerShell)
- End-to-end: a python http.server mock returning OpenAI-style SSE on 127.0.0.1 (or Anthropic-style `event:`-framed SSE for `/v1/messages`) plus a config.json pointing at it exercises any full path (start server and client in the same script; backgrounded servers don't survive between tool calls, and remember `< /dev/null` — the CLI reads piped stdin as prompt text by design); `.github/ci_e2e.py` is the working instance of this pattern — `python .github/ci_e2e.py target/debug/llm` runs it locally against a fresh build
- Remote is `github.com/imjiaoyuan/llm` (branch `main`); CI runs `cargo test` plus a cross-platform e2e smoke on ubuntu/macos/windows, and an interactive REPL pty smoke (`.github/ci_repl.py`: multiline keys, kitty CSI-u folding, `!` tab completion, the ctrl+g editor round-trip — unix only, prints a skip on Windows); tagged `v*` cuts releases (six targets incl. two musl, sha256 checksums). Repo-root `install.sh`/`install.ps1` are the portable installer/updaters over those assets (re-run resolves the latest release and compares versions: `updating old -> new`, equal versions stay unless `LLM_FORCE=1`; `LLM_VERSION`/`LLM_REPO`/`LLM_INSTALL_DIR` overrides, user-level `~/.local/bin` everywhere) — keep them in sync with the release asset names. The Pages site (`https://jiaoyuan.org/llm/`, source = main root) serves only the two installer scripts, never binaries

## Hard constraint: minimal dependencies

Four crates total: `ureq` (sync HTTP+TLS), `serde`/`serde_json` (with the `preserve_order` feature — insertion order matters for JSON output parity), and `unicode-width` (real terminal cell widths; it hard-wraps the chrome: `$` action lines, tool summaries and the logs transcript replay, so those rows match the terminal; the live answer stream hard-wraps too so wrapped rows keep the left margin). No async runtime; the CLI is synchronous throughout — keep new code sync. Everything else is handwritten in-tree: argument parsing (`core/args.rs`, reference-shaped help), a YAML subset (`yaml.rs`), base64 (`b64.rs`), monotonic ULIDs and the turn-timestamp format (`core/db.rs`), reference-style JSON serialization (`jsonfmt.rs`), Damerau-Levenshtein and string helpers (`core/text.rs`), gitignore matching (`gitignore.rs`), directory walks (`core/paths.rs`: `ancestors`/`nearest_dir_up`/`dirs_up` shared by skills, commands-dir and extension discovery), ANSI rendering + the shared TaskView (`term/render.rs`), terminal markdown incl. CJK cell widths (`core/render_md.rs`: `MdStream` for replay + `StyleStream` for live streaming), the color theme (`theme.rs`: the reference's dark palette, one cached `Palette` per stream), platform terminal/shell/editor/pager/clipboard (`platform/`, incl. `platform::interrupt` — the cooperative interrupt flag lives here, core re-exports it), the raw-mode line editor and picker (`term/lineedit.rs`). Extend these instead of adding crates; when a new crate is genuinely justified (correctness or efficiency — `unicode-width` was), say so here and in the commit. Hand-rolled code mimicking the original's behavior is the norm here, not tech debt.

## Architecture
Module map: `providers/` (wire adapters, unified `Msg`/`ToolDef`/`ToolCall`, catalog), `http.rs` (sync POST + SSE, retry/error taxonomy), `core/` (config, threads store, attachments, text, render_md, paths, templates), `term/` (line editor, picker, render/TaskView, ticker), `agent/` (loop, tools, approval, session, compact, ext host, skills, memory, system_prompt), `commands/` (CLI entries: agent, pkg, export, logs). Full request flow, loop discipline, tool/approval rules, extension protocol and rendering contract: `docs/architecture.md`.

## Storage (all under `user_dir()`, overridable via `LLM_USER_PATH`; `~/.llm` on every platform)

Byte-compatible with the reference layout:

- `threads/` — one `<ulid>.jsonl` file per conversation, one `StoredTurn` JSON object per line. Attachments persist as metadata only (path/url/mime); resume replays text only.
- `config.json` — the single settings file (0600, `jsonfmt::dumps_indent(2)`, merge-preserving hand-added keys): providers with inline `api_key` supporting `${ENV_VAR}` expansion everywhere, the top-level `models` family (`default` + optional `thinking` — one shared model every mode starts on; the per-model `options` table), the `agent` behavior section (approval/tools/skills), the `aliases` object (hand-edited; no CLI command edits it), and the two plugin tables (`tools` script tools, `mcpServers`). This file deliberately deviates from the reference's config.toml + keys.json + default_model.txt + model_options.json split.
- `history.jsonl` — the REPL input history: one `{"ts", "text"}` JSON object per line, single-write appends (concurrent processes never interleave), 0600, adjacent submissions deduped at record time, rewritten down to a 1600-entry soft cap once past 2000; the in-memory window is the last 200.
Every agent session persists unless `--no-session`; there is no global logging switch.

## Workflow

- Commits: imperative, lowercase, no prefix ("add interactive agent repl with slash commands"), one
  focused change each. PRs target `main`; releases are cut from `v*` tags by
  `.github/workflows/release.yml`.
- Extensions are the plugin surface: the wire protocol and manifest reference is
  `docs/extensions.md`, runnable examples live in `examples/extensions/` (`wordcount`,
  `websearch` and its TypeScript twin `websearch.ts` (node >= 23.6, or bun/deno),
  `todo` — a port of the reference todo.ts — `repeat_guard.py`, a `tool_call`
  deny gate that breaks identical-call loops, `subagent.py`, which mounts a tool that runs a
  child `llm --json` in its own context window with a `*.md` agent definition from
  `examples/agents/`, and `mcp_bridge.py`, a resident extension that mounts MCP servers as tools
  (`mcp.json` beside the script, stdio transport, one `<server>__<tool>` per tool) — the MCP
  support, per the removed-on-purpose note); refresh both when the host changes.

## Project state

**Removed on purpose — do not reintroduce:** the SQLite logs.db store (migrations, FTS5 `responses_fts`/`turn_search_fts`, the b2 content-addressed message tree, `logstore.rs`, `blake2.rs`, `hash.rs`, `Db`/rusqlite, `llm logs backup`/`--query`/`--search`) — conversations are JSONL thread files now; the hashline edit scheme (exact-match `edit` is the one editor); the legacy `responses`/`conversations` read paths and `llm aliases` as a command (the hand-edited config `aliases` object stays); hooks (`core/hooks.rs`, the config `hooks` table); the embeddings suite (`embed`/`embed-multi`/`similar`/`collections`/`embed-models`, `src/embed/`, embeddings.db, `models.embedding`); fragments; the templates family (`llm templates`, `-t`, `--save` — `core/templates.rs` survives as the internal `$input` engine behind commands-dir prompts); `llm schemas` and every `--schema` source (structured output is cut); the standalone `llm chat` REPL and its tool-less mode (the agent REPL is the single conversational entry point); the agent `remember` tool (memory is hand-edited only); sub-agents outright (`agent/task.rs`, the `task` tool, `output_schema:`, the whole `spawn_agent`/`wait_agent`/`followup_task`/`resume_agent`/`list_agents`/`interrupt_agent` lifecycle, `user_dir/agents/*.md`, `[agent] roles`, `user_dir/subagents/`, `LLM_AGENT_DEPTH`, `--mode json` — subagents return only as an extension, `examples/extensions/subagent.py`, and the reference's schema/lifecycle mode returns only as the one-way `--json` event feed in the deviations below); the old script-tool machinery (`agent/script_tool.rs`, `agent/user_tools.rs`, the config `tools` table, `.llm/tools/`, the `# --- llm-tool ---` table — the extension host replaced it); the MCP client (`agent/mcp.rs`, `mcpServers`, `mcp__server__tool`, `/mcp` — MCP lives in `examples/extensions/mcp_bridge.py`, the extension-form bridge, not in the binary); the checkpoint/`/undo` two-way file-undo scheme (`--fork` replaced it); `/ask`, `/quit`, `/attach` and `/paste` (ctrl+v paste-as-path plus image auto-attach replaced them); the manual `/compact` command (compaction is automatic); rag, `commit`/`why`/`pack`, `scan`/`ping`, one-time legacy migrations; the hand-written PDF extractor and every binary-format parser (binary formats belong to the model's bash tool); `llm keys`, `llm skills`, `llm prompt`, the `llm logs` CLI, `llm install`/`plugins`/`tools` (Python-ecosystem only), `llm completions`, `--async`; and the reference-compat output surface (logs `--id-gt`/`--schema` filters, `models list --json/--options` with fake feature constants, `--schema-multi`, the legacy startup folds: standalone aliases.json, the `logs-off` marker, `[agent] memory = "auto"` with `/memory update|clean`).

**Deliberate deviations — do not "fix" these:** `config.json` replaces the reference's settings-file split; yolo is the default approval mode (the reference asks by default — `--approval-mode ask` / config `approval_mode = "always-ask"` restores it, while the hardcoded refusal list applies in either mode); one shared default model serves every mode (`models.default` + `models.thinking` in config.json; `/model` and `/login`/`/logout` in the REPL own it — the first added provider's first model auto-becomes the default); the agent renders terminal markdown on a TTY through the shared TaskView; attachments serialize per mime and error client-side on unsupported types; option aliases fold into one `-h` row (the reference prints them separately); a missing default model hints instead of falling back to a built-in constant; agent grep is literal by default with an `rg`-backed `regex: true` mode; a the reference shape `update_plan` tool is the one plan surface (a checklist of `{step, status}` with at most one `in_progress`, and the plan lives in the model's own tool call so there is no harness-side plan state); the agent system prompt is resent every turn; `--json` replaces the terminal UI of a *one-shot* task with line-delimited events (`text`/`reasoning`/`tool_start`/`tool_log`/`tool_end`/`turn_end`/`result`) for a supervising process — same usage accounting, persistence and hooks as the terminal path, approvals and diagnostics on stderr, a missing task is a usage error, and the interactive session refuses it; it exists so out-of-process consumers (CI, editors, a subagent extension) can watch a run, not as the reference's structured-output mode; the user directory is `~/.llm`; the plugin system is consent-by-presence — an extension file dropped into an extensions dir may spawn, inherits the ambient env, and keeps no trust store, HTTP transport or restart backoff; `llm -r` is the resume entry (browser → enter question); colors split by role behind one gate (`theme.rs`): the answer text (markdown streaming + replay) renders the reference's dark palette (`mdHeading` #f0c674, accent #8abeb7, code-block green #b5bd68, link #81a2be, gray quotes/rules — truecolor where `COLORTERM` says so, nearest-256 otherwise), while all chrome keeps the original near-monochrome set byte-for-byte — default terminal color for content, bold for emphasis, gray (90/2) for chrome and metadata, red reserved for errors; the only hues are the green preview text on `$` tool lines and the bold-cyan `Allow?` question (diffs: additions default, deletions gray, headers/context dim). `theme::out()`/`theme::err()` cache one `Palette` per stream and `NO_COLOR`, `TERM=dumb` and non-terminal streams strip every SGR byte so redirected output and logs stay escape-free (cursor control like the spinner's `\r\x1b[2K` is not color and stays); never hand-write an escape sequence outside `theme.rs`.
