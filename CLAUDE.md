# CLAUDE.md

This file provides guidance when working with code in this repository.

## Overview

`llm` is a single-binary, terminal-first AI hub in Rust — deliberately two tools in one. The prompting half (prompt, chat, commands, logs) follows the reference implementation in `.reference/llm/` where a feature survives; embeddings, fragments and stored schemas were removed on purpose, so alignment is selective (see Project state). The agent half (`llm agent`: eight tools, approvals, sub-agents, skills, memory, compact, interactive REPL) follows the reference's shape. On top sit kept extensions neither reference has: multimodal input (`-a/--attachment` path/URL/stdin + `--at PATH MIMETYPE` on prompt and agent; in a session ctrl+v pastes the clipboard image as a temp-file path and any local image path in a message auto-attaches) and multimodal output (`--out` for image/tts model kinds: exact name, directory auto-naming, numbered files for `-o n>1`, stdout via `--out -`, overwrite refused).

`.reference/` is read-only, gitignored, and never built. It is the behavioral spec: when command semantics, flags, storage, or output formats are unclear, check it there (`cli.py`, `logs.py`, `models.py`, `parts.py`, `utils.py`, `migrations.py` under `.reference/llm/`; full `--help` texts in `.reference/docs/help.md`; it is not stock 0.32 — it carries migrations m023–m027 with a threads/turns/messages/parts store, ULID ids, and `DEFAULT_MODEL="gpt-5.6-luna"`). Agent mode has no counterpart there — its behavior references are ``the spec` (agent loop, tools, streaming REPL), ``the agent spec` (sub-agents), and ``the approval spec` (approval model), likewise read-only and never built. `AGENTS.md` is the shorter human contributor guide; this file is the authoritative architecture reference.

## Commands

- `cargo build` / `cargo build --release` (release profile: thin LTO, strip, codegen-units=1)
- `cargo test` — unit tests live inline as `#[cfg(test)]` modules across the tree, one behavior per test under a descriptive name (`boundaries_clamp_to_char_edges`, never `test_foo`); run a single one with `cargo test <name>`
- `cargo fmt` before committing; keep `cargo clippy --all-targets` at zero warnings
- `README.md` embeds every command's full `-h` output verbatim — when flags or help text change, refresh the matching block there too (keep it byte-identical)
- Try the binary: `LLM_USER_PATH=/tmp/x cargo run -- "prompt"` — every path resolves under that dir, so smoke tests are hermetic
- Env overrides: `LLM_USER_PATH` (above), `LLM_MODEL` (beats every stored model — mode default, session, template — and loses only to `-m`), `LLM_SHELL` (the shell behind every spawned command: agent bash, `!cmd`; the platform default is `sh`/PowerShell), `LLM_AGENT_DEPTH` (internal — the sub-agent nesting guard)
- End-to-end: a python http.server mock returning OpenAI-style SSE on 127.0.0.1 plus a config.json pointing at it exercises any full path (start server and client in the same script; backgrounded servers don't survive between tool calls, and remember `< /dev/null` — the CLI reads piped stdin as prompt text by design); `.github/ci_e2e.py` is the working instance of this pattern
- Remote is `github.com/imjiaoyuan/llm` (branch `main`); CI runs `cargo test` plus a cross-platform e2e smoke on ubuntu/macos/windows; tagged `v*` cuts releases (six targets incl. two musl, sha256 checksums). Repo-root `install.sh`/`install.ps1` are the portable installer/updaters over those assets (re-run resolves the latest release and compares versions: `updating old -> new`, equal versions stay unless `LLM_FORCE=1`; `LLM_VERSION`/`LLM_REPO`/`LLM_INSTALL_DIR` overrides, user-level `~/.local/bin` everywhere) — keep them in sync with the release asset names. The Pages site (`https://jiaoyuan.org/llm/`, source = main root) serves only the two installer scripts, never binaries

## Hard constraint: minimal dependencies

Five crates total: `ureq` (sync HTTP+TLS), `rusqlite` (bundled SQLite), `serde`/`serde_json` (with the `preserve_order` feature — insertion order matters for JSON output parity), and `unicode-width` (real terminal cell widths; , so hard-wrap rows match the terminal and never soft-wrap into the margin). No async runtime; the CLI is synchronous throughout — keep new code sync. Everything else is handwritten in-tree: argument parsing (`core/args.rs`, reference-shaped help), a YAML subset (`yaml.rs`), base64 (`b64.rs`), sha256 (`hash.rs`), BLAKE2b-16 (`blake2.rs`), monotonic ULIDs and the two timestamp formats (`core/db.rs`), reference-style JSON serialization variants (`jsonfmt.rs`), Damerau-Levenshtein and string helpers (`core/text.rs`), gitignore matching (`gitignore.rs`), ANSI rendering + the shared TaskView (`core/render.rs`), terminal markdown incl. CJK cell widths (`core/render_md.rs`), platform terminal/shell/editor/pager/clipboard (`platform/`), the raw-mode line editor and picker (`term/lineedit.rs`). Extend these instead of adding crates; when a new crate is genuinely justified (correctness or efficiency — `unicode-width` was), say so here and in the commit. Hand-rolled code mimicking the original's behavior is the norm here, not tech debt.

## Architecture

Request flow: `main.rs::dispatch(argv)` routes to a command module → the command resolves a model from config → `providers::ResolvedModel::stream()` dispatches on the config `kind` (`openai-compat` or `anthropic`; media kinds `image`/`tts` go through `providers/media.rs` for `--out`) → `http.rs` does sync POST + SSE parsing with 429/5xx retry (the body read runs on its own thread with 100ms `recv_timeout` slices checking the interrupt flag, so esc works during silent thinking stretches) → events flow back as `http::Event` (`Delta` / `ReasoningDelta` / `Done { usage }`), consumed by `core/render.rs::TaskView`, the agent-style presentation shared by all three modes — spinner (the redraw thread is `term/ticker.rs`), a single dim `thinking ... end` trace line (reasoning is never streamed anywhere), and the dim `secs · ↑in ↓out` footer; answers render as TTY-gated terminal markdown (indent 2 everywhere; pipes stay raw). The agent loop feeds TaskView `AgentUpdate`s and keeps its tool `$` chrome and approvals locally.

- Every command is `pub fn run(argv: &[String]) -> i32` in `src/commands/`, parsing its own flags via `args.rs` specs. Unknown words that aren't subcommands are treated as a prompt, except near-miss subcommand typos (`main.rs::command_hint`: ≥3-char prefix or small Damerau distance) which exit 2 with a did-you-mean instead of spending a model call.
- `providers/message.rs` holds the unified conversation model — `Msg` (User messages carry `attachments: Vec<Attachment>`; `Msg::user_with` builds them), `ToolDef`, `ToolCall` — so the agent depends on providers, never the reverse. Both provider adapters serialize attachments per mime (`attachment_block`): image blocks, OpenAI `file`/`input_audio` plus a text part for `text/*`, Anthropic `document` (base64 PDF or plaintext `text/plain`/`text/csv`); unsupported mimes error client-side before any request leaves, naming the accepted set (`build_body` returns `Result` for exactly that).
- `core/attachments.rs` is the shared loader: `load_args()` runs the `-a`/`--at` entry-flag loop for prompt and agent (the chat preset parses the same specs); `Loaded` keeps path/url/mime/bytes provenance so one load feeds both the wire (`request()`) and the log store (`stored()`); magic-byte `sniff_mime` covers stdin and clipboard bytes; `wants_stdin()` lets `-a -` claim stdin away from the prompt text.
- `llm agent` (`src/agent/`): sync loop over the same `Event` stream — `tools.rs` (eight handwritten tools: read, write, edit with exact-match spans, bash streaming live through `platform::run_shell_stream` in a new session/process group, grep, glob, ls, webfetch; bash previews show as `run` via `display_verb`), `task.rs` (sub-agents = child processes of this binary via `--mode json`; definitions are markdown frontmatter from `user_dir/agents/*.md` plus the nearest `.llm/agents/`, project overriding user; single/chain/parallel `tasks: [...]` modes all stream live `name · progress` lines through a channel drained by the tool thread; `output_schema:` frontmatter or per-call `outputSchema` validates the child's final JSON with a hand-rolled subset validator), `approval.rs` (read/write/exec tiers, ask/yolo, a Linux-style cwd gate — only in-directory reads auto — with symlink-aware `escapes_cwd`, `~/` expansion, critical bash patterns, and a hard root-command block denying sudo/doas/su/pkexec in every mode), `session.rs` (the Session: one model + tools + accumulated history, thinking level, steer queue shared with the KeyWatcher, turn persistence, wire↔storage mapping; `rebuild_tools` is the single registry-build path — built-ins + script tools + MCP mount — shared by the CLI entry and `switch_model`), `mcp.rs` (stdio MCP client: newline-delimited JSON-RPC per the spec, config `mcpServers` table, writer/reader threads with id-correlated pending map, parallel connect that degrades per server, tools mount as `mcp__<server>__<tool>`, `/mcp` listing), `script_tool.rs` (config `tools` table: spawn per call, arguments as one stdin JSON line, stdout is the result, `${VAR}` expansion, builtin-name collisions rejected), `repl.rs` (slash commands `/help /skills /skill:<name> /memory /new /ask /yolo /compact /init /status /mcp /edit /exit`, `!cmd` shell passthrough, unknown `/name` falls back to the commands dir (path-looking words fall through to the task text); session resume happens through `llm logs` (pick a conversation, answer the enter question, which re-enters it in the right mode) — the REPL has no `/resume`; `--fork` branches the loaded session onto a new thread id sharing the message-chain tip via `logstore::fork_thread`), `compact.rs`, `memory.rs` (`~/.llm/LLM.md`, manual + auto regions, `section()` injects into agent/chat system prompts), `skills.rs` (SKILL.md discovery, `skills_block()` caps at 8000 chars), `settings.rs`, `system_prompt.rs` (built-ins + memory + CLAUDE.md/AGENTS.md discovery + skills). `commands/agent.rs` is CLI glue only. While a task runs, KeyWatcher buffers typed lines into the steering queue (dim `queued:` notice) and the loop drains them at the next tool boundary; leftovers become new tasks.
- Plugins ride the same plumbing: every external tool (script or MCP) is Exec-tier, so the approval matrix asks by default and per-tool policies still win; commands-dir subcommands (`core/commands_md.rs`: `~/.llm/commands/*.md` plus the nearest `.llm/commands/`, project wins) resolve in `main.rs` after the typo guard and before the prompt fallback, then run through prompt's template path (preset `Template`), and the REPL reuses them for unknown `/name`.
- `llm chat` is a thin preset over the same machinery (`commands/agent.rs::run_chat` → `execute_mode(args, chat)`): models.chat default, chat's short default system + memory (no agent system prompt, no skills block), `Session::chat_mode` mounting zero tools and stamping turns `mode "chat"`; the REPL, `/edit`, paste and `/mcp` are all shared. The standalone chat.rs REPL was removed on purpose.
- `llm logs` (`commands/logs.rs`): compact list grouped under `agent`/`chat`/`prompt` section headers (mode from per-turn `mode` provenance in turn options, with cwd→agent fallback for pre-provenance sessions), 6-char id prefixes, display-width-truncated previews (CJK counts two cells); `llm logs <mode>|all` filters; bare `llm logs` on a TTY opens an interactive conversation browser through the shared picker — selecting shows the transcript, then one Y-key question continues that conversation in the right session (chat threads via `run_chat`, everything else `run`); `--cid`/`--session`/`--conversation` accept unambiguous id prefixes via `logstore::resolve_conversation`; `--full` keeps the reference's per-turn report.
- `llm models` (`commands/models.rs` + `commands/login.rs`): the single configuration center — mode→provider→model wizard (bare invocation or `models set`), direct `list`/`get`/`set [MODE] MODEL [--thinking]`/`unset`/`key`/`options` forms, `add`/`rm` wrapping the wizard, pickers built from `providers/catalog.rs` (the reference's provider registry, 41 entries incl. four local runtimes: ollama, lm-studio, llama.cpp, vllm, plus openai-image/openai-tts for the `image`/`tts` kinds; OAuth-only and cloud-signature providers deliberately absent). The REPLs have **no `/model`** — each starts on its mode's stored default.
- `src/read/` is the text-file reading module behind the agent's read tool: streaming line windows (`window()`: BufReader, offsets skip without keeping, 500-line/50KB caps distinct from bash/grep's shared `MAX_LINES`, per-line 2000-char cap, one lookahead line decides `Exact` vs `AtLeast` totals), the `BINARY_EXTS` gate + NUL sniff, and `binary_hint` mapping binary formats to local tooling (pdf→pdftotext, bam/cram→samtools, parquet/hdf5→duckdb, office→libreoffice). Memory stays bounded by the window; nothing but text is ever parsed.
- `src/core/logstore.rs` is the content-addressed store: messages hash as `"b2:" + blake2b16(canonical_json({"parent", "message"}))`, chains append to a thread's stored tip (never rebuilt lossily), `fork_thread` shares a tip for session branching, turns carry provenance (options/schema/usage) and refresh `turn_search` for FTS. All logs.db SQL lives here (or `db.rs` for DDL/backup); `Db.conn` is private behind a store-layer accessor. The legacy `responses`/`conversations` tables are still created for reference schema parity but never read. `core/schemas.rs` resolves `--schema` inputs (inline JSON / DSL / file).
- `term/lineedit.rs`: raw-mode line editor with completion (VMIN=0/VTIME=1 polled reads where `read()==0` means timeout, never EOF — EOF is the 0x04 byte), the KeyWatcher steering buffer, and the ONE picker `pick(title, items, echo)` used by every list in the tool — arrow-move + type-to-filter in the fuzzy-filter shape (UTF-8 accumulates across bytes so CJK filters work, space-separated terms AND-match case-insensitively, enter returns the original index; there is deliberately no second picker variant).
- Model ids are namespaced `provider/model`; the `aliases` object in config.json maps friendly names on top (a legacy standalone aliases.json folds in once and is ignored).

## Storage (all under `user_dir()`, overridable via `LLM_USER_PATH`; `~/.llm` on every platform)

Byte-compatible with the reference layout:

- `logs.db` — full m001–m027 schema (prewritten `_llm_migrations` rows keep the reference tool from replaying migrations); rollback journal, no WAL; FTS5 `responses_fts` + `turn_search_fts` with bm25(10.0, 1.0) ranking. Attachments persist as attachment parts in every mode; resume replays text only.
- `config.json` — the single settings file (0600, `jsonfmt::dumps_indent(2)`, merge-preserving hand-added keys): providers with inline `api_key` supporting `${ENV_VAR}` expansion everywhere, the top-level `models` family (`prompt`/`agent`/`chat` entries as `{model, thinking?}` — bare `llm "prompt"` uses `models.prompt`; the per-model `options` table; loose legacy files still fold in at startup), the `agent` behavior section (approval/tools/roles/skills/memory), the `aliases` object (hand-edited; no CLI command edits it), the `logging` boolean, and the two plugin tables (`tools` script tools, `mcpServers`). This file deliberately deviates from the reference's config.toml + keys.json + default_model.txt + model_options.json split.
Prompt logging is the `logging` boolean in config.json (a legacy `logs-off` marker file still counts as off); chat always logs.

## Project state

**Removed on purpose — do not reintroduce:** the hashline edit scheme (`hashline_edit` + `read`'s `hashline: true` anchors + md5; `edit`'s exact-match uniqueness check is the one editor now), the legacy `responses`/`conversations` read paths (the tables stay in the schema for reference parity; every store this binary writes is threads/turns), `llm aliases` as a CLI command (the config.json `aliases` object and its resolution remain, hand-edited), hooks (`core/hooks.rs` and the config `hooks` table), the embeddings suite (`embed`/`embed-multi`/`similar`/`collections`/`embed-models`, `src/embed/`, embeddings.db, the `models.embedding` scalar — orphaned when rag died), fragments (commands, `core/fragments.rs`, Template fragment fields, all wiring; the db tables stay for legacy turns), the templates family (`llm templates`, `-t`, `--save`, `--schema t:NAME`; `core/templates.rs` survives as the internal substitution engine behind custom commands, which inherit its `attachments`/`attachment_types` frontmatter), `llm schemas`, the stored-id and `t:template` `--schema` sources (inline JSON / DSL / file remain), the standalone `llm chat` REPL (chat is a tool-less agent preset), `/resume` in the REPL (logs is the entry), `/attach` and `/paste` (ctrl+v paste-as-path plus image-path auto-attach replace them), rag (knowledge-base Q&A), `commit`/`why`/`pack` (git prompt wrappers), `scan`/`ping` (provider auto-detection), one-time legacy migrations, the hand-written PDF extractor and every binary-format parser (binary formats belong to the model's bash tool), `llm login`/`logout`/`keys` (absorbed into `llm models`), `llm skills` (lives in the agent REPL's `/skills`), `llm install`/`uninstall`/`plugins`/`tools` (Python-ecosystem only), `llm completions` (hardcoded lists drifted with every command change), and `--async`.

**Deliberate deviations — do not "fix" these:** `config.json` replaces the reference's settings-file split; `llm models` is the single configuration center (dual-form: bare subcommands interactive, full arguments direct; the first added provider's first model auto-becomes the prompt default); prompt and chat render terminal markdown on a TTY through the shared TaskView; `llm logs` defaults to the compact mode-sectioned list with the interactive browser (piped `--full` stays byte-identical to the reference shape); the typo guard exits 2 instead of silently prompting (the reference's `DefaultGroup` sends any unknown word to the model; `llm prompt <text>` is the explicit escape); attachments serialize per mime and error client-side on unsupported types; option aliases fold into one `-h` row (the reference prints them separately); sub-agent outputs validate against a hand-rolled JSON Schema subset; `turns.response_json` stays NULL; `--out` media paths are not logged; a missing default model hints instead of falling back to a built-in constant; agent storage extends parts with ToolCall/ToolResult, logs tool results as role "tool" and compaction summaries as system messages (all schema-compatible); agent grep is literal-only; the agent system prompt is resent every turn; the user directory is `~/.llm`; the plugin system is config-consent — script tools spawn per call, the MCP client speaks newline-delimited JSON-RPC per the MCP spec (the reference agent's shared LSP client frames with Content-Length instead), inherits the ambient env with explicit `${VAR}` overrides rather than an allowlist, and keeps no trust store, HTTP transport or restart backoff; commands-dir subcommands resolve after the typo guard and never shadow built-ins; `llm chat` shares the agent binary's machinery instead of being its own REPL, and `llm logs` is the single resume entry (browser → enter question); all interactive chrome is near-monochrome — default terminal color for content, bold for emphasis, gray (90/2) for chrome and metadata, red reserved for errors; the only hues are the green preview text on `$` tool lines and the bold-cyan `Allow?` question.
