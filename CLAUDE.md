# CLAUDE.md

This file provides guidance when working with code in this repository.

## Overview

`llm` is a single-binary, terminal-first AI hub in Rust — deliberately two tools in one. The prompting half (prompt, commands, logs) follows the reference implementation in `~/work/references/llm/` where a feature survives; embeddings, fragments and stored schemas were removed on purpose, so alignment is selective (see Project state). The agent half (`llm agent`: tools, approvals, sub-agents, skills, memory, compact, interactive REPL) follows the reference's shape. On top sit kept extensions neither reference has: multimodal input (`-a/--attachment` path/URL/stdin + `--at PATH MIMETYPE` on prompt and agent; in a session ctrl+v pastes the clipboard image as a temp-file path and any local image path in a message auto-attaches).

The behavioral references live outside the repo in `~/work/references/` (read-only, never built; the repo's `.gitignore` still lists a `.reference` dir in case one is symlinked back). That tree is the spec: when command semantics, flags, storage, or output formats are unclear, check it there (`cli.py`, `logs.py`, `models.py`, `parts.py`, `utils.py`, `migrations.py` under `~/work/references/llm/llm/`; full `--help` texts in `~/work/references/llm/docs/help.md`; it is not stock 0.32 — it carries migrations m023–m027 with a threads/turns/messages/parts store, ULID ids, and `DEFAULT_MODEL="gpt-5.6-luna"`). Agent mode has no counterpart there — its behavior references are `the behavioral spec` (agent loop, tools, streaming REPL), `the rust port notes` (sub-agents), and `the approval reference` (approval model), likewise read-only and never built. `AGENTS.md` is the shorter human contributor guide; this file is the authoritative architecture reference.

## Commands

- `cargo build` / `cargo build --release` (release profile: thin LTO, strip, codegen-units=1)
- `cargo test` — unit tests live inline as `#[cfg(test)]` modules across the tree, one behavior per test under a descriptive name (`boundaries_clamp_to_char_edges`, never `test_foo`); run a single one with `cargo test <name>`
- `cargo fmt` before committing; keep `cargo clippy --all-targets` at zero warnings
- `README.md` embeds every command's full `-h` output verbatim — when flags or help text change, refresh the matching block there too (keep it byte-identical)
- Try the binary: `LLM_USER_PATH=/tmp/x cargo run -- "prompt"` — every path resolves under that dir, so smoke tests are hermetic
- Env overrides: `LLM_USER_PATH` (above), `LLM_MODEL` (beats every stored model — the shared default, session, template — and loses only to `-m`), `LLM_SHELL` (the shell behind every spawned command: agent bash, `!cmd`; the platform default is `sh`/PowerShell), `LLM_AGENT_DEPTH` (internal — the sub-agent nesting guard)
- End-to-end: a python http.server mock returning OpenAI-style SSE on 127.0.0.1 (or Anthropic-style `event:`-framed SSE for `/v1/messages`) plus a config.json pointing at it exercises any full path (start server and client in the same script; backgrounded servers don't survive between tool calls, and remember `< /dev/null` — the CLI reads piped stdin as prompt text by design); `.github/ci_e2e.py` is the working instance of this pattern — `python .github/ci_e2e.py target/debug/llm` runs it locally against a fresh build
- Remote is `github.com/imjiaoyuan/llm` (branch `main`); CI runs `cargo test` plus a cross-platform e2e smoke on ubuntu/macos/windows, and an interactive REPL pty smoke (`.github/ci_repl.py`: multiline keys, kitty CSI-u folding, `!` tab completion, the ctrl+g editor round-trip — unix only, prints a skip on Windows); tagged `v*` cuts releases (six targets incl. two musl, sha256 checksums). Repo-root `install.sh`/`install.ps1` are the portable installer/updaters over those assets (re-run resolves the latest release and compares versions: `updating old -> new`, equal versions stay unless `LLM_FORCE=1`; `LLM_VERSION`/`LLM_REPO`/`LLM_INSTALL_DIR` overrides, user-level `~/.local/bin` everywhere) — keep them in sync with the release asset names. The Pages site (`https://jiaoyuan.org/llm/`, source = main root) serves only the two installer scripts, never binaries

## Hard constraint: minimal dependencies

Four crates total: `ureq` (sync HTTP+TLS), `serde`/`serde_json` (with the `preserve_order` feature — insertion order matters for JSON output parity), and `unicode-width` (real terminal cell widths; it hard-wraps the chrome: `$` action lines, tool summaries and the logs transcript replay, so those rows match the terminal; the live answer stream itself is verbatim and lets the terminal soft-wrap). No async runtime; the CLI is synchronous throughout — keep new code sync. Everything else is handwritten in-tree: argument parsing (`core/args.rs`, reference-shaped help), a YAML subset (`yaml.rs`), base64 (`b64.rs`), monotonic ULIDs and the turn-timestamp format (`core/db.rs`), reference-style JSON serialization (`jsonfmt.rs`), Damerau-Levenshtein and string helpers (`core/text.rs`), gitignore matching (`gitignore.rs`), directory walks (`core/paths.rs`: `ancestors`/`nearest_dir_up`/`dirs_up` shared by skills, sub-agents, commands-dir and drop-in tool discovery), ANSI rendering + the shared TaskView (`term/render.rs`), terminal markdown incl. CJK cell widths (`core/render_md.rs`), platform terminal/shell/editor/pager/clipboard (`platform/`, incl. `platform::interrupt` — the cooperative interrupt flag lives here, core re-exports it), the raw-mode line editor and picker (`term/lineedit.rs`). Extend these instead of adding crates; when a new crate is genuinely justified (correctness or efficiency — `unicode-width` was), say so here and in the commit. Hand-rolled code mimicking the original's behavior is the norm here, not tech debt.

## Architecture
Model resolution for prompt/agent is one shared chain, `providers::resolve_run_model` (`-m` > `LLM_MODEL` > session/template > the stored default; a bare model name served by more than one provider errors listing the `provider/model` candidates instead of silently taking the first in config order), and every provider `/models` fetch plus the messages API build headers through `providers::auth_headers(kind, key)` (Anthropic: `x-api-key` + `anthropic-version`; openai-compat: Bearer).

Request flow: `main.rs::dispatch(argv)` routes to a command module → the command resolves a model from config → `providers::ResolvedModel::stream()` dispatches on the config `kind` (`openai-compat` or `anthropic`) → `http.rs` does sync POST + SSE parsing under a the reference shape, deliberately lean error taxonomy (`HttpError::class()`: Connection/RateLimited/Server retry, Auth/InvalidRequest fatal, ContextTooLarge sniffed from 400 bodies — OpenAI "maximum context length", Anthropic "prompt is too long", Google "exceed context limit" — Stream for post-start drops, Interrupted for esc); retries resend with ±10%-jittered backoff (1s→30s for responses, a separate 5s→60s×12 budget for connection failures), honoring a server Retry-After when sent, sleeping in 50ms interruptible slices with a dim `retrying in Ns` notice, extracting `x-request-id`/`cf-ray` into the error text, and never resending after output was already handed out (a mid-stream drop surfaces instead of replaying); a stream that ends without a completion marker (`[DONE]`/`message_stop`) is surfaced as truncation rather than a clean turn (a clean FIN on a half-delivered answer must not be stored as a finished round), and an Anthropic `message_start` seeds the input/cached token counts that the edge merges with the `message_delta` output counts a stream silent past 300s is an idle error, not a hung task. The body read runs on its own thread with 100ms `recv_timeout` slices checking the interrupt flag, so esc works during silent thinking stretches → events flow back as `http::Event` (`Delta` / `ReasoningDelta` / `Done { usage }`), consumed by `term/render.rs::TaskView`, the agent-style presentation shared by all three modes — spinner (the redraw thread is `term/ticker.rs`), a single dim `thinking ... end` trace line (reasoning is never streamed anywhere), and the dim `secs · ↑in ↓out` footer (plus `cache N%` when the provider reports prompt-cache hits); answers stream character-immediately and verbatim in a left-indent-2 block on a TTY — each of the model's own lines carries the margin, and `BlockStream` hard-wraps at the terminal width (re-read at every line start, so a resize applies from the next row; unicode-width cells, tabs advancing to the next 8-column stop from the absolute column; a space within the last few cells breaks early so word middles are usually spared) so wrapped continuation rows keep the margin instead of soft-wrapping to column 0 (only the `>` prompt and `$` tool chrome sit at column 0), and the spinner never starts over a dangling partial row (`Renderer::has_dangling` guards it); pipes stay raw. The agent loop feeds TaskView `AgentUpdate`s and keeps its tool `$` chrome and approvals locally. Every outbound request also carries `http::identity_headers(url)` — merged in `send_raw`/`get_with` rather than per adapter — which is a real `user-agent` (`llm/<version>`, never ureq's library default) plus, for `opencode.ai` hosts, the `x-opencode-session` conversation id OpenCode Go/Zen demands with a 400 `MissingSessionID` when it is absent: one ulid per process (`http::session_id()`), pinnable across processes with `LLM_SESSION_ID`.

- Every command is `pub fn run(argv: &[String]) -> i32` in `src/commands/`, parsing its own flags via `args.rs` specs. Unknown words that aren't subcommands are treated as a prompt, except near-miss subcommand typos (`main.rs::command_hint`: ≥3-char prefix or small Damerau distance) which exit 2 with a did-you-mean instead of spending a model call.
- `providers/message.rs` holds the unified conversation model — `Msg` (User messages carry `attachments: Vec<Attachment>`; `Msg::user_with` builds them), `ToolDef`, `ToolCall` — so the agent depends on providers, never the reverse. Both provider adapters serialize attachments per mime (`attachment_block`): image blocks, OpenAI `file`/`input_audio` plus a text part for `text/*`, Anthropic `document` (base64 PDF or plaintext `text/plain`/`text/csv`); unsupported mimes error client-side before any request leaves, naming the accepted set (`build_body` returns `Result` for exactly that).
- `core/attachments.rs` is the shared loader: `load_args()` runs the `-a`/`--at` entry-flag loop for prompt and agent; `Loaded` keeps path/url/mime/bytes provenance so one load feeds both the wire (`request()`) and the log store (`stored()`); magic-byte `sniff_mime` covers stdin and clipboard bytes; `wants_stdin()` lets `-a -` claim stdin away from the prompt text.
- `llm agent` (`src/agent/`): sync loop over the same `Event` stream — `tools.rs` (nine handwritten tools: read, write, edit with exact-match spans plus a whitespace-flexible fallback (per-line trailing whitespace, CRLF, smart quotes/dashes — the reference's fuzzy matching) so a near-miss oldText still applies, bash streaming live through `platform::run_shell_stream` in a new session/process group, grep, glob, ls, webfetch, update_plan (the multi-step checklist: steps with pending/in_progress/completed statuses, at most one in progress; Read-tier, previews as `N step(s)`); bash previews show as `run` via `display_verb`), `task.rs` (sub-agents = child processes of this binary via `--mode json`; definitions are markdown frontmatter from `user_dir/agents/*.md` plus the nearest `.llm/agents/`, project overriding user; single/chain/parallel `tasks: [...]` modes all stream live `name · progress` lines through a channel drained by the tool thread; `output_schema:` frontmatter or per-call `outputSchema` validates the child's final JSON with a hand-rolled subset validator; results cap at 50KB and child token spend shows on the done progress line; plus the reference shape lifecycle tools `spawn_agent`/`wait_agent`/`followup_task`/`resume_agent`/`list_agents`/`interrupt_agent` — `spawn_agent` background-starts a child whose conversation persists to `user_dir/subagents/<id>.jsonl` and returns the agent_id immediately, `wait_agent` blocks on the live child, `followup_task`/`resume_agent` respawn the child with `--session <id> -d <subagents>` to continue its thread, and the live-children table is `Session.live_agents`, RAII-killed on drop), `approval.rs` (read/write/exec tiers, ask/yolo, a Linux-style cwd gate — only in-directory reads auto — with symlink-aware `escapes_cwd`, `~/` expansion, a danger table that forces a manual prompt in every mode, yolo included — rm in any shape, mkfs, dd to devices, raw-disk redirects, chmod/chown -R from /, system-account writes, curl|sh, shutdown/poweroff/halt, fork bombs, nc -e; the prompt offers no session-always option and an 'a' keypress is downgraded to one-shot so one approval never whitelists bash past the table — and a hard root-command block denying sudo/doas/su/pkexec in every mode), `session.rs` (the Session: one model + tools + accumulated history, thinking level, steer queue shared with the KeyWatcher, turn persistence, wire↔storage mapping; `rebuild_tools` is the single registry-build path — built-ins + script tools + MCP mount — shared by the CLI entry and `switch_model`), `mcp.rs` (stdio MCP client: newline-delimited JSON-RPC per the spec, config `mcpServers` table, writer/reader threads with id-correlated pending map, parallel connect that degrades per server, tools mount as `mcp__<server>__<tool>`, `/mcp` listing), `script_tool.rs` + `user_tools.rs` (script tools from two homes: the config `tools` table, and drop-in files from `~/.llm/tools/` plus the nearest `.llm/tools/` walking up, project winning by name — an executable with a `# --- llm-tool: name ---` manifest header runs itself (`description:`/`args: name (type) desc` lines build the schema), a `name.json` manifest points at an external command; both spawn per call, arguments as one stdin JSON line, stdout is the result, `${VAR}` expansion, builtin-name collisions rejected; `/tools` lists drop-ins plus MCP servers), `repl.rs` (slash commands `/help /clear /skills /skill:<name> /memory /ask /yolo /compact /init /status /mcp /tools /exit`, `!cmd` shell passthrough with bash-style tab completion — command positions (first word, or right after `|`/`&`/`;`) complete executable names from `$PATH`, later words complete filesystem paths as typed, dirs getting a trailing `/`, hidden entries only after a dot prefix — unknown `/name` falls back to the commands dir and then to plain task text, a near miss of a known command only prints a did-you-mean and sends nothing; slash and `!` input echoes bold in the line editor; session resume happens through `llm logs` (pick a conversation, answer the enter question, which re-enters it in the agent session) — the REPL has no `/resume`; `--fork` branches the loaded session onto a new thread id sharing its turns so far via `threads::Store::fork_thread`), `compact.rs`, `memory.rs` (`~/.llm/LLM.md`, one manual region; `section()` injects into the agent system prompt, `/memory add` appends a line — the agent `remember` tool and the `[agent] memory` setting were removed, memory is manual-only), `skills.rs` (SKILL.md discovery, `skills_block()` caps at 8000 chars), `settings.rs`, `system_prompt.rs` (built-ins + memory + CLAUDE.md/AGENTS.md discovery + skills; a continuation from a stored prompt keeps it verbatim and refreshes only the trailing cwd line). The system prompt stays byte-identical across every round: providers cache by request prefix (DeepSeek context caching, Anthropic prompt caching), so any per-turn mutation re-bills the whole history at cache-miss price. Both adapters engage the cache deliberately: the anthropic one sends explicit `cache_control` breakpoints (on the system text block, caching tools+system together, falling back to the last tool when there is no system; on the last content block of the conversation tip once history exists, skipping the never-resent one-shot prompt) because Messages API caching is opt-in, and folds `cache_read`+`cache_creation` into `Usage.input` to match openai-compat's whole-prompt `prompt_tokens`; the openai-compat side is automatic server-side, its hit count parsed from all three usage shapes (`providers::cache_hit_tokens`: DeepSeek, OpenAI, OpenRouter). `commands/agent.rs` is CLI glue only. While a task runs, KeyWatcher buffers typed lines into the steering queue (dim `queued:` notice) and the loop drains them at the next tool boundary; leftovers become new tasks.
- Plugins ride the same plumbing: every external tool (script or MCP) is Exec-tier, so the approval matrix asks by default and per-tool policies still win; commands-dir subcommands (`core/commands_md.rs`: `~/.llm/commands/*.md` plus the nearest `.llm/commands/`, project wins) resolve in `main.rs` before the typo guard (an exact `.llm/commands/<name>.md` match is not a typo of a builtin) and before the prompt fallback, then run through prompt's template path (preset `Template`), and the REPL reuses them for unknown `/name`.
- `llm logs` (`commands/logs.rs`): compact list grouped under `agent`/`prompt` section headers, one line per thread, 6-char id prefixes, display-width-truncated previews (CJK counts two cells); `llm logs <mode>|all` filters; bare `llm logs` on a TTY opens an interactive conversation browser through the shared picker — selecting shows the transcript, then one Y-key question continues that conversation in the agent session via `run`; `--cid`/`--conversation` accept unambiguous id prefixes via `threads::Store::resolve_thread`; `--full` keeps the per-turn report.
- `llm models` (`commands/models.rs`) picks the shared default model every mode starts on — provider→model→thinking wizard (bare invocation or `models set`), direct `set MODEL [--thinking]`/`get`/`unset` forms, plus `list`/`key`/`options` (options resolve bare/alias names to the qualified id the table is keyed by). The provider lifecycle lives in `llm login`/`llm logout` (`commands/login.rs`): the wizard (catalog + Cloudflare/Azure URL templates + custom), the direct `login NAME [KEY]` form (an omitted KEY falls back to the catalog entry's env var as a `${VAR}` reference; `--base-url`/`--kind` register any custom endpoint non-interactively; an entry left model-less by a failed fetch is refreshed by re-running instead of erroring), and `logout` (picker or NAME; clearing the default when it pointed at the removed provider). Pickers build from `providers/catalog.rs` (the reference's provider registry, 40 entries incl. opencode-go in both wire kinds and four local runtimes: ollama, lm-studio, llama.cpp, vllm; OAuth-only and cloud-signature providers deliberately absent). The REPLs have **no `/model`** — each starts on the stored default.
- `src/read/` is the text-file reading module behind the agent's read tool: streaming line windows (`window()`: BufReader, offsets skip without keeping, the agent tool clamps to a 2000-line window under the shared 50KB cap — the reference's values, so one read covers a typical source file), per-line 2000-char cap, one lookahead line decides `Exact` vs `AtLeast` totals), the `BINARY_EXTS` gate + NUL sniff, and `binary_hint` mapping binary formats to local tooling (pdf→pdftotext, bam/cram→samtools, parquet/hdf5→duckdb, office→libreoffice). Memory stays bounded by the window; nothing but text is ever parsed.
- `src/core/threads.rs` is the conversation store: one JSONL file per thread under `user_dir/threads/<ulid>.jsonl`, one `StoredTurn` object per line (id, ts, mode, model, cwd, system, prompt, response, reasoning, usage, options, schema, and the round's wire `messages` as `StoredMsg`). `append_turn` appends a line (a None thread id starts a fresh thread), `read_thread` returns turns oldest-first, `latest_thread`/`resolve_thread`/`fork_thread`/`recent_threads`/`counts` serve the resume and list surfaces. Resume is the reference shape: a thread id reopens its file — no SQL, no FTS, no b2 content addressing. `core/schemas.rs` resolves `--schema` inputs (inline JSON / DSL / file).
- `term/lineedit.rs`: raw-mode line editor with completion (VMIN=0/VTIME=1 polled reads where `read()==0` means timeout, never EOF — EOF is the 0x04 byte), the KeyWatcher steering buffer, and the ONE picker `pick(title, items, echo)` used by every list in the tool — arrow-move + type-to-filter in the fuzzy-filter shape (UTF-8 accumulates across bytes so CJK filters work, space-separated terms AND-match case-insensitively, enter returns the original index; there is deliberately no second picker variant). The buffer is multiline (the reference shape): `\r` submits while ctrl+j (`\n`), alt+enter, shift/ctrl+enter, a lone `\` before enter (a doubled `\\` submits literally) and bracketed paste insert real newlines — the platform clears ICRNL so `\r`/`\n` stay distinct, and the kitty keyboard protocol's disambiguate flag (`ESC[>1u`) is pushed only for the read's duration so modified enter arrives as CSI-u keys; kitty terminals that re-encode plain ctrl+letter as CSI-u (ctrl+c = `CSI 99;5u`) are folded back to the C0 byte so every ctrl binding keeps working, and a lone or CSI-27u ESC interrupts like ctrl-c (one press clears the line, two exit; the watcher and approval prompts keep plain-ESC semantics); ↑/↓ recall history only while browsing, from an empty buffer, or parked at the very start of the top line — the working draft is saved on first recall and restored on the way back past the newest entry — and otherwise walk logical lines with a sticky preferred column; readline keys round it out (ctrl-a/e cross lines at boundaries, ctrl-k/u/w + alt-d feed a single-entry kill buffer that survives submit, ctrl-y yanks, alt-b/f and ctrl-arrows move by word); ctrl+g round-trips the draft through `$VISUAL`/`$EDITOR` (guards dropped, cooked mode, then re-acquired); pastes over 10 lines or 1000 chars become an atomic `[paste #N +L lines]` token whose payload expands at submit; history persists to `history.jsonl` (below).
- Model ids are namespaced `provider/model`; the `aliases` object in config.json maps friendly names on top (a legacy standalone aliases.json folds in once and is ignored).

## Storage (all under `user_dir()`, overridable via `LLM_USER_PATH`; `~/.llm` on every platform)

Byte-compatible with the reference layout:

- `threads/` — one `<ulid>.jsonl` file per conversation, one `StoredTurn` JSON object per line. Attachments persist as metadata only (path/url/mime); resume replays text only.
- `config.json` — the single settings file (0600, `jsonfmt::dumps_indent(2)`, merge-preserving hand-added keys): providers with inline `api_key` supporting `${ENV_VAR}` expansion everywhere, the top-level `models` family (`default` + optional `thinking` — one shared model every mode starts on; legacy `prompt`/`agent` entries migrate on read, prompt first, and collapse on the next write; the per-model `options` table), the `agent` behavior section (approval/tools/roles/skills), the `aliases` object (hand-edited; no CLI command edits it), the `logging` boolean, and the two plugin tables (`tools` script tools, `mcpServers`). This file deliberately deviates from the reference's config.toml + keys.json + default_model.txt + model_options.json split.
- `history.jsonl` — the REPL input history: one `{"ts", "text"}` JSON object per line, single-write appends (concurrent processes never interleave), 0600, adjacent submissions deduped at record time, rewritten down to a 1600-entry soft cap once past 2000; the in-memory window is the last 200.
Prompt logging is the `logging` boolean in config.json; `llm prompt -n` refuses `-c`/`--session` — you cannot continue an earlier conversation under a run that writes nothing.

**Deliberate deviations — do not "fix" these:** `config.json` replaces the reference's settings-file split; one shared default model serves every mode (`models.default` + `models.thinking` in config.json; `llm models` picks it, `llm login`/`llm logout` own the provider lifecycle — the first added provider's first model auto-becomes the default); prompt and agent render terminal markdown on a TTY through the shared TaskView; `llm logs` defaults to the compact mode-sectioned list with the interactive browser (piped `--full` stays byte-identical to the reference shape); the typo guard exits 2 instead of silently prompting (the reference's `DefaultGroup` sends any unknown word to the model; `llm prompt <text>` is the explicit escape); attachments serialize per mime and error client-side on unsupported types; option aliases fold into one `-h` row (the reference prints them separately); sub-agent outputs validate against a hand-rolled JSON Schema subset; a missing default model hints instead of falling back to a built-in constant; agent grep is literal-only; the agent system prompt is resent every turn; the user directory is `~/.llm`; the plugin system is config-consent — script tools spawn per call, the MCP client speaks newline-delimited JSON-RPC per the MCP spec (the reference agent's shared LSP client frames with Content-Length instead), inherits the ambient env with explicit `${VAR}` overrides rather than an allowlist, and keeps no trust store, HTTP transport or restart backoff; commands-dir subcommands win over the typo guard yet never shadow built-ins; `llm logs` is the single resume entry (browser → enter question); all interactive chrome is near-monochrome — default terminal color for content, bold for emphasis, gray (90/2) for chrome and metadata, red reserved for errors; the only hues are the green preview text on `$` tool lines and the bold-cyan `Allow?` question.
